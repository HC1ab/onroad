## 검토 메모 (반영 전 확인할 것)

**1~3 공통: 지금 지도에 찍히는 점의 범위**
- 현재 점은 "후보 횡단보도"만이다(기록값이 기준식보다 짧음 `gap_s > 0` 그리고 목적지 노출 1개 이상). 기준식을 넘는 점만 있는 셈이라, 1번의 "여유가 있을수록 초록"을 보이려면 기준식보다 긴(여유 있는) 횡단보도까지 점으로 받아야 한다.
- 그러려면 계약·서버 변경이 필요하다: 후보 점 API(`/api/crosswalks/candidates`)는 후보만 준다. 전체 횡단보도 점을 주는 새 경로(또는 `only_candidates=false` 같은 파라미터)와 파이프라인 결과가 있어야 한다. 전국 전체 점은 수가 많아 지도 범위(bbox)·줌 단계 제한이 필요하다.
- 결정할 것: (a) 지금처럼 후보만 두고 짧은 정도(`gap_s`)만 흰색→빨간색으로 칠한다 / (b) 전체 횡단보도로 넓혀 초록~흰~빨강을 쓴다.

**1번: 색과 표현 원칙**
- 빨강·초록 조합은 적록색약에서 구분이 어렵다. 웹 규칙(`web/CLAUDE.md`)이 색맹 대응을 요구하므로 빨강–흰–파랑(또는 주황–흰–청록) 같은 발산형 색이 대안이다.
- 범례 문구에 판정·단정 표현을 쓰지 않는다(R5). 예: "기준식보다 짧음(초) ↔ 기준식보다 여유(초)".
- 녹색신호시간 정의(점멸 포함 여부)가 확정되기 전이므로, 색의 기준값(흰색이 되는 지점)은 `gap_s = 0` 으로 두고 "정의 미확정"을 범례에 함께 적는다.
- 지금 읍면동 채색도 주황 계열이라 점 색이 채색과 겹쳐 보일 수 있다. 점 테두리·크기로 구분 필요.

**2번: 필터 대상 값**
- 무엇의 "이상·이하"인지 정해야 한다: 짧은 초(`gap_s`)가 가장 자연스럽다. 다른 후보: 노출 수(`exposure_cnt`), 횡단보도 길이(`length_m`).
- 범례 아래 "짧은 초 [N]초 이상 / 이하" 형태가 기존 화면과 맞다. 후보 수 표시(범례 "후보 횡단보도 N곳")도 필터 결과로 바뀌어야 한다.
- CSV 내려받기에 필터를 반영할지도 정한다(현재는 전체).

**3번: 클러스터링**
- MapLibre GeoJSON 소스의 기본 클러스터 기능으로 가능하다(추가 라이브러리 없음).
- 묶음의 색을 정해야 한다: 개수만 보여줄지, 묶인 점의 최대·평균 짧은 초로 칠할지(1번 색과 맞춤).
- 지금 점은 지도 범위(bbox)로만 받으므로, 전국을 멀리서 볼 때 점 수가 많아지면 서버 응답 크기도 함께 봐야 한다.

**4번: 시도 → 시군구 → 동 단계 이동**
- 지금: 첫 화면은 샘플 지역(부산 일부) 근처로 열리고, 지도는 항상 읍면동 단위로 칠한다. 시도·시군구 이동은 헤더의 드롭다운(W7 #23)으로만 된다. 동을 누르면 오른쪽에 상세가 열린다.
- 바뀌는 것: 지도를 누르는 단계형 흐름. 전국(시도별 칠함) → 시도 클릭(확대, 시군구별 칠함) → 시군구 클릭(확대, 읍면동별 칠함) → 동 클릭(상세).
- 필요한 데이터
  - 시도·시군구 경계: 지금 경계 파일은 읍면동만 있다. 화면에서 합치면 전국 3,500여 개 동을 합쳐야 해 느리다. 파이프라인(D6 #9)이 시도·시군구 경계 파일도 같이 만드는 쪽이 낫다 → 계약(`boundaries`)에 단계 추가 필요.
  - 시도·시군구 단계의 값: 읍면동 값을 분석 횡단보도 수로 가중해 화면에서 합칠 수 있다(짧음 비율 = 짧은 수 합 / 분석 수 합). 고령 비율은 인구 가중이 맞는데 지금 응답에 인구 수가 없다 → 계약에 인구 칼럼 추가 또는 서버 집계 필요.
- 화면에서 정할 것
  - 위로 돌아가는 방법: 경로 표시(전국 > 부산광역시 > 해운대구) 클릭, 지도 빈 곳 클릭 등
  - 헤더 드롭다운과 지도 클릭을 같은 상태로 맞추기(한쪽을 바꾸면 다른 쪽도 바뀜)
  - 사분면·상위 목록이 각 단계에서 무엇을 보여줄지(그 단계의 하위 지역들 / 계속 읍면동)
  - 후보 점은 어느 단계부터 보일지(예: 시군구 단계부터. 1~3번 클러스터링과 연결)
- 샘플은 부산 2개 구뿐이라 전국 → 시도 단계는 실데이터(전국 경계·결과)가 들어와야 제대로 확인할 수 있다.

**5번 (질문): 검증 범위는 전국인가, 선택 지역인가**
- 답: 전국 기준이 맞다(PRD 7장). 검증은 "이 방법(기준식·지표)이 믿을 만한가"를 보는 것이라 지역의 성질이 아니다.
- 선택 지역마다 검증을 바꾸지 않는 이유
  - 표본: 시군구 하나는 읍면동 수십 개라 상관계수·무작위 비교(p값)가 크게 흔들린다.
  - 여러 지역을 돌려 보면 우연히 "안 맞는" 지역이 나오는데, 그게 그 지역 문제처럼 읽힌다.
  - 서버는 요청 때 계산하지 않는다. 지역마다 하려면 파이프라인이 모든 지역 조합을 미리 계산해야 한다.
- 항목별
  - V1 현장 실측: 원래 부산 20~30곳. 지역 선택과 관계없음.
  - V2 속도 민감도, V3 사고다발지역 연관성, V5 회귀: 전국. V3의 무작위 비교는 이미 "같은 시군구 안에서" 섞으므로 지역 차이가 반영돼 있다.
  - V4 축 독립성: PRD에 "시도별·도시/농촌별로도 계산"이 있고 응답에 `by_group`이 있다. 지역을 고른 상태면 그 시도 줄을 강조해 보여줄 수는 있다(새 계산 없이).
- 화면에서 보완할 점(선택)
  - 검증 화면에 "전국 기준 · 지도의 지역 선택과 관계없음"을 적는다. 지금은 범위 표시가 없다.
  - V4의 시도별 결과에서 선택한 시도를 강조한다.

**6번: 검증 화면의 설명 부족**
- 지금 카드마다 있는 것: 제목, "묻는 것"(질문 한 줄), 그림·수치, "해석 주의". 페이지 위에는 "결과가 기대와 달라도 그대로 표시 · 연관성이며 인과 아님" 한 줄뿐이다.
- 빠진 것 (PRD 7장 검증 표에는 있음)
  - **왜 하는가:** 이 검증이 틀리면 지도 결과를 어떻게 다르게 읽어야 하는지(예: V1이 크게 어긋나면 녹색신호시간 정의가 바뀌어 전체 해석이 달라짐)
  - **쓴 데이터:** 어떤 자료를 썼는지(V1 부산 현장 측정 N곳, V3 사고다발지역 과거·최근 연도, V4 고령 인구·시설 위치 등)와 기준 시점
  - **방법:** 무엇과 무엇을 비교했는지 쉬운 말로(V2 속도별 순위 상관·상위 N 중복, V3 같은 시군구 안 무작위 추출과 겹침 비교, V4 상관과 반경 안/밖 비교, V5 다른 요인 통제 회귀)
  - **읽는 법:** 수치가 어느 쪽이면 무엇을 뜻하는지(상관 1에 가까우면 흔들리지 않음, 무작위 대비 배수 1보다 크면 우연보다 많이 겹침, p값의 뜻)
- 페이지 위 안내도 부족하다: 검증이 왜 필요한지(기준식 비교 결과를 그대로 믿어도 되는지 확인), 다섯 가지가 각각 무엇을 맡는지 한눈에 보는 요약.
- 반영 방법 후보
  - 카드 틀(`ValidationCard`)에 "쓴 데이터", "방법", "읽는 법" 칸 추가. 처음엔 접어 두고 펼치기
  - 문구는 PRD 7장 표에서 가져오고 R5 표현 원칙을 지킨다("부족" 대신 "기준식보다 짧음", 단정 표현 금지)
  - 쓴 데이터의 기준 시점·건수는 화면에 박지 않고 응답(`validation`, `meta`)에서 받는 게 맞다 → 필요하면 계약에 항목 추가(예: V1 측정 지역·기간, V3 연도 구분)

**7~8번: 사고 데이터 채색과 상세 표시**
- 지금 쓰는 사고 데이터: 도로교통공단 "보행노인 사고다발지역"(다발지역 폴리곤 + 사고·사망·중상 건수). 결정 기록 006에 따라 **과거 연도는 노출 플래그(`crash_zone_past`)**, **최근 연도는 검증 V3에만** 쓴다. 상세 패널에는 횡단보도별 플래그 "사"(과거 연도 다발지역)만 있다.
- **주의: 최근 연도 사고로 채색하면 V3 검증이 무너진다.** V3는 "과거 정보로 고른 후보가 그 뒤 사고와 겹치는가"를 보는데, 최근 연도 사고를 지도에 칠해 우선순위 판단에 쓰면 같은 자료로 고르고 검증하는 순환이 된다. 채색·상세에 쓰는 것은 **과거 연도 다발지역**으로 한정하고 범례에 연도를 적는다.
- 다발지역은 "읍면동별 사고 건수"가 아니다. 반경 안 사고가 기준 이상인 지점만 지정된 것이라, 읍면동 값으로 쓰려면 정의가 필요하다. 후보:
  - (a) 동 안 과거 연도 다발지역 수
  - (b) 동 안 다발지역에 걸친 횡단보도 비율
  - (c) 다발지역의 사고·사망·중상 건수 합 (동 경계에 걸친 다발지역 배분 규칙 필요)
- 2021년에 다발지역 선정 기준이 바뀌었다(006). 연도 분할이 팀 결정 대기라, 채색에 쓸 연도도 그 결정을 따라야 한다.
- 필요한 변경: 파이프라인(D5 #8)이 읍면동 사고 지표를 계산 → 계약 `areas` 항목·`area_crosswalks`(또는 상세 요약)에 필드 추가 → 서버 적재 → 웹. 현재 응답에는 읍면동 사고 값이 없다.
- 화면
  - 채색 기준 선택: 범례에 "채색 기준: 기준식보다 짧은 비율 / 사고다발(과거 연도)" 전환. 사분면 세로축(65세 이상 비율)은 그대로 둘지 함께 정한다.
  - 사고 채색도 단일 계열 명도로(색맹 대응). 다발지역 0인 동이 대부분이라 "없음"과 "자료 없음"을 구분해 칠한다.
  - 상세: 동 요약 칸에 "노인 보행사고 다발지역(과거 연도 YYYY~YYYY) N곳, 사고 N건". 다발지역 폴리곤을 지도에 겹쳐 보이는 것도 후보.
  - 문구: 판정 표현 금지(R5). "사고다발지역(과거 연도)" 그대로 쓰고, "다발지역이 아님 ≠ 사고 없음"을 적는다.

**9번 (질문): 노출 반경의 뜻**
- 뜻: 각 횡단보도에서 반경 N m 안에 노인이 오가는 목적지(경로당·마을회관, 전통시장, 노인·장애인 보호구역, 과거 연도 노인 보행사고 다발지역)가 있는지 보는 거리. 1개 이상이면 "노출"이고, 기록값이 기준식보다 짧으면서 노출이 있으면 "점검 우선순위 후보"가 된다.
- 300m인 이유: 노인보호구역을 시설 출입문에서 300m(필요하면 500m) 안으로 지정하는 법령 기준(결정 기록 005). 200m는 범위를 좁혔을 때 결과가 얼마나 바뀌는지 보는 민감도 값.
- 반경이 바꾸는 것: 후보 수(범례 "후보 횡단보도 N곳", 상위 목록 후보 수), 후보 점, 상세의 노출 플래그.
- 반경이 바꾸지 않는 것: 읍면동 채색(짧은 비율), 사분면 두 축(짧은 비율·65세 이상 비율). 그래서 반경을 바꿔도 지도 색은 그대로라 헷갈릴 수 있다.
- 지금 범례 문구: "기본 300m. 200·500m는 반경 가정에 따라 결과가 얼마나 바뀌는지 보는 용도"뿐. 무엇을 기준으로 한 반경인지(횡단보도 중심), 무엇을 찾는지(목적지 4종), 무엇이 바뀌는지가 빠져 있다.
- 보강 후보: 범례 "노출 반경" 옆에 도움말(ⓘ) — "횡단보도에서 이 거리 안에 경로당·시장·보호구역·사고다발지역(과거)이 있으면 노출. 후보 수와 점만 바뀌고 지도 색은 바뀌지 않음". 6번(검증 설명)과 같은 방식으로 맞춘다.

**10번: 표본 부족 기준 미표시**
- 기준: `config.yaml`의 `min_sample: 5` — 읍면동 안 분석 가능한 횡단보도가 5곳 미만이면 `low_sample`(회색 빗금, 상위 목록·사분면 순위 제외).
- 지금 화면: 범례 "표본 부족 (순위 제외)", 툴팁·상세 "표본 부족 (순위 제외)"만 있고 "몇 곳 미만"인지, 그 동의 분석 횡단보도 수가 몇인지 나오지 않는다(상세에는 분석 횡단보도 수가 있음).
- 계약 문제: 기준값(5)이 응답에 없다. `areas` 스키마 설명에만 "표본 하한(config.yaml) 미만"이라고 있다. 화면에 숫자를 박으면 config와 어긋날 수 있으니(분석 설정값은 config.yaml에서만), 응답에 넣는 게 맞다 → `areas.thresholds` 또는 `meta`에 `min_sample` 추가(계약 변경, 하위 호환).
- 보강 후보: 범례 "표본 부족 (분석 횡단보도 5곳 미만, 순위 제외)", 툴팁 "표본 부족 · 분석 3곳 (5곳 미만)". 9번 도움말과 같은 방식.

**11번: 횡단보도 선택과 정보**
- 지금
  - 지도의 후보 점을 누르면 팝업에 "점검 우선순위 후보 · 기준식보다 N초 짧음 · 노출 N개"만 나온다. 연장·기록 녹색시간·필요 시간은 없다.
  - 동 상세 패널의 횡단보도 표에는 연장·기록·필요·짧은 초·노출이 있고, 행을 누르면 지도가 그 점으로 이동한다. 지도 → 표 방향 연결은 없다.
  - 후보가 아닌 횡단보도는 지도에 점이 없다(1번과 같은 문제).
- 바뀌는 것: 점을 누르면 그 횡단보도의 정보 카드(연장, 기록 녹색신호시간, 기준식 필요 시간 = 7 + 연장/속도, 짧은 초, 노출 종류별 표시, 소속 동)를 보여준다. 상세 표의 같은 행도 강조한다.
- 데이터: 후보 점 응답(`candidates`)의 속성은 `cw_id, adm_cd, gap_s, exposure_cnt`뿐이다. 정보 카드를 위해서는
  - (a) 후보 점 속성에 `length_m, green_s, t_need_s, flags` 추가(계약 변경, 응답이 커짐), 또는
  - (b) 점을 누르면 그 동의 상세(`/api/areas/{adm_cd}/crosswalks`)를 받아 `cw_id`로 찾기(계약 변경 없음, 상세가 적재된 동만 가능)
- 표시 원칙: "기록값이 기준식보다 N초 짧음"(R5), 녹색신호시간 정의 미확정 표시, 필요 시간에 쓴 속도(현재 선택 속도)를 함께 적는다.

**12번: 시간 없는 횡단보도(위치만) 표시**
- 이런 횡단보도는 파이프라인 F1에서 "녹색신호시간 결측"으로 제외되고 제외 사유 표에 건수만 남는다. 지금 결과·계약·DB 어디에도 위치가 없다.
- 필요한 변경: 파이프라인이 제외된 횡단보도 중 좌표가 있는 것을 따로 내보냄(제외 사유 포함) → 계약에 새 레이어(예: `/api/crosswalks/unanalyzed?bbox=`, 속도·반경과 무관) → 서버 적재 → 웹 레이어("분석 제외(녹색시간 없음)", 속 빈 점, 기본 꺼짐, 범례에서 켜고 끔).
- 제외 사유는 녹색시간 결측 말고도 연장 결측·범위 밖(연장>80m, 녹색>200s 등)이 있다. "시간 없음"만 보일지, 제외 사유별로 보일지 정한다.
- 1번(전체 횡단보도 표시), 3번(클러스터링)과 같은 지도 레이어 구조로 묶어 설계하는 게 좋다.
- 표시: "분석 제외 · 녹색신호시간 기록 없음". 빈 점이 "문제 없음"으로 읽히지 않게 범례에 적는다.

**13~14번: 사용자 입력 — 지금 구조와 충돌, 먼저 결정 필요**
- 지금 원칙: API는 읽기 전용(쓰기 경로 없음, `server/CLAUDE.md`), 로그인 없음(`web/CLAUDE.md`), 서버는 요청 때 계산하지 않는다. 공개 URL이라 아무나 쓸 수 있는 입력은 장난·잘못된 값이 섞일 수 있다.
- 입력값을 공식 결과와 섞으면 안 된다: 사용자가 넣은 녹색시간이 지도 채색·후보·검증에 바로 들어가면 공공데이터 기준 결과와 구분이 사라진다. 들어가더라도 "사용자 입력(검토 전)"으로 따로 표시해야 한다.
- 선택지
  - (a) **브라우저 안에서만**: 입력값은 그 사람 브라우저에만 저장(로컬 저장소), 화면에서 바로 계산해 "내 입력 기준" 결과를 따로 보여주고, CSV로 내보내 팀이 검토 후 파이프라인에 넣는다. 서버·계약 변경 없음. 원칙과 충돌 없음.
  - (b) **서버에 저장**: 쓰기 API·입력 테이블·검토(승인) 절차·남용 방지(속도 제한, 간단한 인증)가 필요. 읽기 전용 원칙을 바꾸는 결정이라 PRD·결정 기록부터 고쳐야 한다. 11/3 마감 안에는 무리.
- **13번(녹색시간 직접 입력)**: (a)로 하면 입력한 횡단보도만 기준식(7 + 연장/속도)과 바로 비교해 보여줄 수 있다. 읍면동 비율·사분면까지 다시 계산하는 건 화면에 계산 로직을 두는 것이라(지금은 파이프라인만 계산) 범위를 정해야 한다.
- **14번(V1 현장 실측 입력)**: V1은 "기록값 − 실측값" 차이의 평균·분포라 화면에서 계산하기 쉽다. 입력 칸: 횡단보도 선택(또는 cw_id), 실측 녹색(초), 실측 점멸(초), 측정 일시. 결과: 차이 평균, 점멸 포함 추정 건수, 산점도(기존 V1 카드 형식 그대로).
  - 현장 실측 원자료·사진은 저장소에 올리지 않는다(R1 `field/photos/`). 입력값 내보내기(CSV)는 B-validation 구역(`validation/`)으로 넘기는 흐름.
  - 공식 V1 결과(팀 실측)와 사용자 입력 결과를 같은 카드에 섞지 않는다. "내 측정값으로 보기" 전환으로 분리.
- 권장: 마감 전에는 (a)로 14번만(현장 실측 팀 작업과 바로 연결됨), 13번·서버 저장은 MVP 이후로.

**15번: 지도에서 실측 입력 → V1 반영 (14번 구체화, 11번과 연결)**
- 흐름: 지도에서 횡단보도 점 선택 → 정보 카드(11번)에 "실측 입력" → 실측 녹색(초)·점멸(초)·측정 일시 입력 → 저장하면 검증 V1 카드가 그 값을 포함해 다시 계산 → 같은 정보 카드에 "기록 N초 / 실측 N초 (차이 ±N초)" 표시, 지도 점에 실측 완료 표시(테두리 등).
- 선행: 11번(횡단보도 선택·정보 카드). 그리고 V1 측정 지점은 시군구·연장 구간별로 고르므로 후보가 아닌 횡단보도도 많다 → 후보 아닌 횡단보도도 점으로 고를 수 있어야 한다(1번 또는 12번 레이어).
- 계산: V1은 속도·반경과 무관(기록값 vs 실측값). 차이 = 기록 − 실측. 한 곳을 여러 번 재면 평균, 측정 횟수 표시. 점멸 포함 추정: 기록값이 "실측 녹색 + 실측 점멸"에 가까운 건수.
- 저장: 13~14번 결정(a)대로 브라우저 안에만 저장하고 CSV 내보내기. 공식 V1(팀 실측, 서버 결과)과 "내 입력"은 V1 카드에서 전환으로 분리 표시. 지도 정보 카드에도 "내 입력(검토 전)" 표시.
- 입력 검증: 0 이하·200초 초과 같은 값 막기(F1 정제 기준과 같은 범위, 값은 응답·설정에서 받기).
- 화면 문구: "기록값이 실측보다 N초 김/짧음". 사진 첨부는 받지 않는다(R1 `field/photos/`).

**16번: 하단 바 → About 페이지**
- 지금 하단 바: 한계 고지 한 줄(녹색신호시간 정의 미확정, 읍면동 평균의 한계, 인과 아님, "점검 우선순위 후보이며 판정이 아님")과 출처(전국횡단보도표준데이터, admdongkor CC BY 4.0, 행안부 고령 인구현황).
- 규칙과 충돌: `web/CLAUDE.md`·PRD F9는 **모든 화면 하단에 한계 고지 한 줄과 출처를 항상 표시**하라고 한다. admdongkor(CC BY 4.0)는 출처 표기가 이용 조건이다. 완전히 빼면 규칙과 라이선스 조건에 어긋난다.
- 절충안: 하단에는 아주 짧은 한 줄만 남긴다(예: "점검 우선순위 후보이며 판정이 아님 · 정의 미확정 · 출처·한계 자세히 →"). 자세한 한계 설명·출처 목록·라이선스·방법 요약·데이터 기준일은 About(`#/about`, 헤더 탭 "지도 | 검증 | About")으로 옮긴다. 지도 오른쪽 아래 배경지도 출처(OpenFreeMap·OSM)는 그대로.
- About에 모으기 좋은 것: 9번(노출 반경 뜻), 10번(표본 부족 기준), 6번 일부(검증 방법 요약), 기준식 설명(7 + 연장/속도), 데이터 기준일(`meta.built_at`, `ref_month`), 결정 기록 링크.
- 규칙을 바꾸려면 `web/CLAUDE.md`·PRD F9 문구를 "하단에 한계 요약과 출처 링크, 자세한 내용은 About"으로 고치는 결정이 먼저 필요하다(공통 문서라 main 직행 PR).
