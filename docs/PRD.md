전국 횡단보도의 기록된 초록불 시간을 기준식 필요시간과 전수 비교하고, 고령 거주 비율과 목적지·사고 노출을 겹쳐 점검이 필요한 지역과 횡단보도 후보를 찾는 웹 서비스다. 팀 길건너친구들(안), 프로젝트명 "한 박자"(영문안 GreenGap).

## 1. 배경과 문제 정의

보행 신호 시간의 기준은 진입 7초에 연장 1m당 1초(1m/s)를 더한 값이다[^seoul-signal][^han2020]. 보행약자가 많은 곳에는 0.8m당 1초(0.8m/s)를 적용하고[^seoul-signal], 노인·어린이보호구역에는 0.7m/s까지 적용한다[^seoul-2024][^kyeonggi]. 문제는 이 기준을 전국 모든 횡단보도에 적용해 본 점검이 눈에 띄지 않는다는 점이다.

**선행 사례는 모두 선정된 일부 지점의 개선이다.** 출처를 확인한 항목과 아직 원문을 찾지 못한 항목을 나눠 표시했다. **(원문 미확인)** 표시는 발표 자료에 넣기 전 반드시 다시 확인한다.

- 국토부·경찰청(2025-05-15): 전통시장·병원 인근 등 횡단보도 1,000곳의 보행 기준을 1초당 1m에서 0.7m 수준으로 완화하고, 보행신호 자동연장 시스템을 올해 221곳까지 늘린다(목표치)[^molit2025]
- 서울시(2024-10): 보호구역이 아닌 횡단보도 123곳을 동별 고령자 비율과 최근 10년 교통사고로 선정, 길이에 따라 3\~6초 연장, 68곳 완료·55곳 연내 예정[^seoul-2024]
- 제주(2025): 고령자 주거·방문 비율이 높은 제주시 139곳의 보행신호를 개선하고, 그중 99곳을 0.7m/s 기준으로 평균 4.8초 연장[^kyunghyang]. 기사 안의 세부 합계가 맞지 않아 이 범위까지만 인용한다
- 부산(2018): 111곳, 2\~3초 연장 **(원문 미확인)**
- 노인보호구역은 노인 인구 1만 명당 2.2곳으로 어린이(21.5곳)보다 적고, 노인 보행사고의 98%가 보호구역 밖에서 난다는 보도가 있다(2023 기준)[^seoulshinmun]. 기사에 원자료 기관이 적혀 있지 않아 원문을 찾기 전에는 발표에 쓰지 않는다

**차별점 한 문장:** 우리가 찾은 범위에서는 전국 횡단보도 전수에 대해 부족 초수를 계산하고 고령 거주 비율과 목적지·사고 노출을 겹쳐 점검 우선 지역을 보여준 사례를 찾지 못했다. 이는 "못 찾았다"일 뿐 "없다"는 증명이 아니다.

**목적지 기준은 정부도 이미 썼다.** 국토부·경찰청은 전통시장·병원 인근을[^molit2025], 서울시는 동별 고령자 비율과 사고를 기준으로 골랐다[^seoul-2024]. 거주나 목적지 기준 자체는 차별점이 아니다. 차별점은 같은 기준으로 전국을 전수 계산해 **아직 부족한 곳이 남아 있는지** 확인하는 것이다. "이미 조정됐을 것"이라는 가설도 V4(7장)로 직접 확인한다.

**하지 않기로 한 것:** 고령화를 예측해 미리 늘린다는 접근은 뺐다. 지금 이미 부족한 곳이 있는지가 먼저이고, 시군구 이하 단위의 장래인구추계가 있는지 확인하지 못했다.

## 2. 목표와 범위

MVP의 목표는 **"부산 횡단보도 전수 → 횡단보도별 적용 속도(3단계) → 기준 적용 시 필요 시간·이유·고령 보행자 커버리지 → 정책 반영 점검·검증"을 URL 하나로 보여주는 것**이다.

**목표**

- 부산 횡단보도 각각에 대해 필요시간(7 + L/v)과 기록된 보행시간을 비교한다. v는 노인보호구역 0.7m/s, 대형 전통시장 주변·그 외는 이용자 고령 비율로 정한다(3장 v2 산출식).
- 읍면동 단위로 평균 추가 초와 65세 이상 인구 비율을 2축 사분면에 배치하고, 횡단보도 단위로 단계·이유·커버리지를 보여준다. 단계별 우선순위 목록으로 "점검 우선순위 후보"를 찾는다.
- 결과를 검증한다: 현장 실측 5~10곳(V1), 속도 민감도(V2), 사고다발지역 연관성(V3), 축 독립성(V4), 시장 보정 근거(V6), 보호구역 0.7 반영률(V7).
- **(v2)** 부산 횡단보도마다 적용 속도를 3단계로 정해 기준 적용 시 필요 시간과 추가 초, 그 이유, 커버리지(시간 안에 건널 수 있는 보행자 비율)를 보여준다. 노인보호구역 주변의 0.7m/s 기준 반영 여부를 점검한다(V7).
- 11/3까지 Ubuntu 서버에 배포해 URL로 접속 가능한 상태로 만든다 (서버가 프론트 파일과 읽기 전용 API를 함께 제공한다).

**비목표**

- 고령화 예측, 신호 연장 효과나 교통 영향 시뮬레이션
- 개별 횡단보도를 "위험"이나 "위반"으로 단정하는 표현
- 로그인, 사용자 입력 저장(쓰기 API 없음), 실시간 데이터 연동, LLM 해설
- 신호 시간 변경 권고안 자동 생성. v2의 "기준 적용 시 필요 시간"은 공식 기준식에 단계별 속도를 넣은 계산 결과이며, 운영 기관에 대한 권고가 아니다

**절반만 만들면 남는 것:** 사분면 지도와 상위 N 목록까지만 완성해도 "전수 계산 + 고령 비율"이라는 핵심은 남는다. 검증(P0 아래쪽)이 빠지면 근거가 약해지므로 컷 라인은 기능이 아니라 검증 쪽에서 치지 않는다.

## 3. 핵심 산식과 표현 원칙

모든 판정은 아래 한 식에서 나오고, 속도 v만 바꿔 세 번 계산한다.

```latex
T_{need}(v) = 7 + \frac{L}{v}, \qquad \text{gap}(v) = T_{need}(v) - G_{rec}
```

L은 횡단보도연장(m), G\_rec는 기록된 녹색신호시간(s)이다. gap이 0보다 크면 그 속도 기준에서 "기록값이 기준식보다 짧음"으로 표시한다. 예를 들어 32m 횡단보도는 1.0m/s에서 39초, 0.8m/s에서 47초, 0.7m/s에서 약 52.7초가 필요하다.

**T\_need는 녹색 점멸까지 포함한 전체 보행신호 시간이다.** 경찰청 편람은 보행신호를 녹색시간과 녹색점멸시간으로 나눈다[^chae2022]. 그래서 데이터의 녹색신호시간이 점멸을 빼고 기록한 값이면 대부분의 횡단보도가 잘못 "짧음"으로 나온다. 게이트 A와 현장 실측(V1)을 가장 먼저 하는 이유다([결정 기록 002](decisions/002-녹색신호시간-정의와-비교-방법.md)).

**"짧음"은 규정에 어긋난다는 뜻이 아니다.** 0.8·0.7m/s는 보행약자 지역과 보호구역의 기준이라, 일반 횡단보도가 그 기준보다 짧아도 규정에 어긋나는 것은 아니다. 이 도구는 "그 속도로 걷는 사람에게는 짧게 기록되어 있다"는 것만 보여준다.

| 속도 v | 의미 | 근거 |
| --- | --- | --- |
| 1.0m/s | 일반 기준 | 진입 7초 + 1m당 1초[^seoul-signal]. 경찰청 매뉴얼의 일반 보행속도[^han2020]. 일반인 15퍼센타일 보행속도 1.01m/s와 비슷하다[^han2020] |
| 0.8m/s | 보행약자 기준 | 보행약자가 많은 곳 0.8m당 1초[^seoul-signal]. 노인 15퍼센타일 보행속도 0.85m/s에 가깝다[^han2020] |
| 0.7m/s | 노인·어린이보호구역 기준 | 보호구역 최대 0.7m/s[^seoul-2024]. 2019년 연구용역을 거쳐 경찰청 「교통신호기 설치·운영·관리 업무편람」(2022)에서 교통약자 기준이 0.8 → 0.7m/s로 개정[^chae2022][^kyeonggi]. 국토부 2025 대책(1,000곳)[^molit2025]과 제주 사례[^kyunghyang]도 0.7m/s를 썼다. 지팡이·휠체어 사용 노인 15퍼센타일 0.73m/s에 가깝다[^han2020] |

신호는 평균이 아니라 느린 보행자(대개 15퍼센타일)에 맞춰 설계한다. 미국 MUTCD도 3.5ft/s(약 1.07m/s)를 쓰고 느린 보행자가 많으면 더 낮은 속도를 권한다[^mutcd][^noyce]. 그래서 세 속도를 모두 계산해 어느 집단 기준에서 짧은지 보여준다.

**값과 데이터를 고른 이유:** 기준식·속도·65세·읍면동·중앙값·표본 하한·노출 시설·반경·데이터 선택의 근거와 출처는 [결정 기록](decisions/README.md) 001~007에 정리했다. 아직 확인하지 못한 항목(녹색신호시간 정의, 매뉴얼 원문, 사고다발지역 기준 변경)도 함께 적었다.

**노출 두 층(수정):** 거주 노출은 읍면동 65세 이상 비율이고, 목적지 노출은 횡단보도 반경 N m 안에 경로당·전통시장·노인보호구역이 있는지, 사고다발지역(과거 연도) 안인지다. 기본 반경은 300m이고 200/500m로 민감도를 본다. 300m(최대 500m)는 노인보호구역을 시설 주 출입문 반경 300m 이내(필요시 500m)로 지정하는 규정에 맞춘 값이다[^zone-rule]. 경로당은 노인여가복지시설로 노인이 정기적으로 모이는 곳이고[^welfare], 전통시장·병원은 정부가 고령자 통행이 잦은 곳으로 꼽았다[^molit2025]. 200m는 범위를 좁힌 민감도로 별도 근거는 없다. 병원은 좌표 필드를 확인한 뒤 추가한다(P2).

**사분면(v1 초안, v2에서 변경):** v2는 가로축을 읍면동 평균 추가 초로 바꾼다(결정 004·009). 아래는 v1 설명이다. 가로축은 읍면동 안에서 분석 가능한 횡단보도 중 gap > 0인 비율, 세로축은 65세 이상 인구 비율이다. 65세는 인구 통계가 읍면동 단위로 65세 이상과 전체 인구를 제공하고[^mois], 사고다발지역 자료도 65세 이상을 노인으로 정의해서 맞춘 기준이다[^koroad]. 가중합 점수는 만들지 않는다. 경계선 기본값은 전국 중앙값이고 화면에서 조절할 수 있게 한다. 짧음 비율 지표, 중앙값 경계, 가중합을 만들지 않는 것은 외부 근거가 없는 **팀 판단**이며 이유는 [결정 기록 004](decisions/004-지표와-사분면-경계.md)에 적었다. 오른쪽 위 칸이 “점검 우선순위 후보” 지역이다.

**후보 횡단보도 정의(v1, v2에서 변경):** v2는 노출 개수 대신 단계별 적용 속도 기준 추가 초가 큰 순으로 우선순위를 정한다. 아래는 v1 설명이다. 어느 속도 기준에서든 gap > 0이면서 목적지·사고 노출 플래그가 1개 이상인 횡단보도다. 우선순위는 해당하는 노출의 개수로 정하고, 같으면 짧은 초가 큰 순으로 정한다. 어느 노출이 더 중요한지는 정하지 않으며 가중합 점수도 만들지 않는다. 거주 비율이 낮아도 목적지 노출로 잡힐 수 있다. 플래그가 없다는 것은 노출이 없다는 뜻이 아니다(시설 데이터 누락 가능).

**표본 하한(초안):** 읍면동 안의 분석 가능 횡단보도가 5곳 미만이면 사분면에서 회색으로 표시하고 순위에서 뺀다. 5는 외부 근거가 없는 임의값(팀 판단)이며 데이터 분포를 본 뒤 조정한다([004](decisions/004-지표와-사분면-경계.md)). 전체 데이터를 받은 뒤 3·5·10곳을 비교한다.

**그 밖의 임계값(모두 팀 판단, 외부 근거 없음):** 아래 값은 발표에서 "임의값이며 바꿨을 때 결론이 바뀌는지 확인했다"고 밝힌다. 모두 `config.yaml`에서 바꿔 다시 돌릴 수 있다.

| 값 | 하는 일 | 왜 이 값인가 | 확인 방법 |
| --- | --- | --- | --- |
| 연장 상한 80m | 넘으면 입력 오류로 보고 제외 | 국내 대로의 횡단보도도 대부분 이보다 짧다는 가정 | 전체 데이터에서 상위 값을 직접 확인 |
| 녹색 상한 200초 | 넘으면 입력 오류로 보고 제외 | 보행신호 하나가 신호주기 대부분을 차지할 수 없다는 가정 | 위와 같음 |
| 게이트 A 경고선 40% / 1% | 1.0m/s 짧음 비율이 이 범위를 벗어나면 필드 정의부터 의심 | 신호는 1.0m/s 기준으로 설계되므로 대부분 기준을 넘어야 정상이라는 추론 | V1 현장 실측으로 판단 |

**v2 산출식: 횡단보도별 적용 속도 3단계 (결정 009)**

기준식은 그대로 쓰고 속도 v를 횡단보도마다 정한다. 가중합 점수는 만들지 않는다.

```latex
T_{req} = \max\left(G_{rec},\ 7 + \frac{L}{v}\right), \qquad \text{add} = T_{req} - G_{rec}, \qquad
\text{coverage}(T) = P\left(\text{보행속도} \ge \frac{L}{T - 7}\right)
```

| 단계 | 조건 (반경 300m) | 이용자 고령 비율 p | 적용 속도 v |
| --- | --- | --- | --- |
| 1 | 노인보호구역 (O1 코드 1·01) | 고령자 기준 | 0.7m/s (현행 보호구역 기준) |
| 2 | 대형 전통시장 (점포 200개 이상, 산업용재 등 제외) | 주민 고령 비율 + 0.137 | 섞인 분포에서 85%가 건너는 속도 |
| 3 | 그 외 | 반경 안 주민 고령 비율 (행정동 면적 가중) | 섞인 분포에서 85%가 건너는 속도 |

- 섞인 분포: 일반인(평균 1.29, 15퍼센타일 1.01m/s)과 고령자(평균 1.13, 15퍼센타일 0.85m/s) 보행속도 분포[^han2020]를 p로 섞는다(정규 근사, 가정). v는 0.7~1.0m/s로 자른다.
- 목표 커버리지 85%는 15퍼센타일 설계 관례[^han2020][^mutcd]를 그대로 쓴 것이다. 90·95%는 민감도.
- 2단계 +0.137은 부산 지하철 무임 승차 비율로 측정했다(V6): 대형 시장 300m 안 역 7곳이 주민 고령 비율을 감안해도 +10.95%p(p=0.004), 고령 비율 10%p당 무임 8.0%p.
- 경로당은 주민 고령 비율과 겹쳐 뺀다. 사고다발지역은 검증 전용이다(008).
- **화면의 커버리지는 고령 보행자 기준으로 통일한다.** 단계마다 이용자 구성이 달라도 같은 잣대로 비교하기 위해서다. 이용자 구성은 속도 v를 정하는 데만 쓴다.
- 시장 보정은 역 7곳 기반이라 범위로 표기한다(+6~16%p, 수안·부전역을 빼면 하한). 고령자 15퍼센타일 속도는 다른 국내 실측(0.76m/s)으로 민감도를 함께 보여준다.
- 계수표와 근거 수준은 [결정 009](decisions/009-추천-보행시간-3단계.md)에 있다. 계수 값은 모두 `config.yaml`에서 읽는다.

**표현 원칙**

- 허용: “점검 우선순위 후보”, “기록값이 기준식보다 짧음”, (v2) “기준 적용 시 N초(+M초)”, “커버리지 A% → B%”
- 금지: “위험”, “위반”, “불법”, “부적합”, “시간을 늘려야 한다”는 단정
- 커버리지는 “시간 안에 건널 수 있는 보행자 비율”이다. “신뢰도”나 “정확도”로 부르지 않는다
- 이 도구는 인과를 주장하지 않는다. 부족 판정과 노출, 사고의 “겹침·연관”까지만 말하고 “\~ 때문에 위험”이나 “늘리면 사고가 준다”는 쓰지 않는다
- 읍면동 평균은 그 동의 개별 횡단보도 이용자 구성을 뜻하지 않는다(생태학적 오류[^robinson]). About 탭과 지역 상세에 표시한다.
- 녹색신호시간 필드가 점멸 시간을 포함하는지 확인하기 전에는 결과를 “부족”으로 부르지 않는다(4장 게이트). 데이터 페이지에는 항목 정의가 없다[^crosswalk]([결정 기록 002](decisions/002-녹색신호시간-정의와-비교-방법.md)).

## 5. 사용자와 시나리오

주 사용자는 발표 현장의 심사위원이고, 실제 활용 관점의 사용자는 지자체 교통안전 담당자다. MVP는 두 사용자가 같은 화면을 쓰도록 만든다.

| 사용자 | 알고 싶은 것 | 화면에서 보는 것 |
| --- | --- | --- |
| 심사위원 | 이 분석이 맞는가, 신뢰할 수 있는가 | 부산 지도, 기록값/3단계 기준 전환, 계수와 근거, 검증 결과 페이지 |
| 지자체 담당자 | 우리 관할에서 먼저 볼 곳이 어디인가 | 시군구 필터, 횡단보도 우선순위 목록, 정보 카드(기준 적용 시간·이유·커버리지) |
| 시민(보조) | 우리 동네는 어떤가 | 읍면동 상세 카드 |

**발표 데모 흐름 (v2, 약 3분)**

1. 문제: 부산 보행시간의 83%가 1.0m/s 기준식 값이다. 고령 보행자 커버리지는 약 70%다.
2. 방법: 공식 식은 그대로, "누가 건너는가"만 바꿨다(3단계). 계수는 모두 출처가 있다(계수와 근거 화면).
3. 지도: "기록값 / 3단계 기준"을 전환하며 평균 추가 초가 큰 동과 횡단보도가 어디에 몰리는지 보여준다.
4. 발견(V7): 같은 0.7m/s 기준인데 어린이보호구역 150m 안은 28%가 반영됐고, 노인보호구역 300m 안은 14%(222곳 중 31곳)다. 우선순위 목록 상위가 대부분 이곳이다.
5. 카드: 한 횡단보도를 눌러 기준 적용 시간, 이유 한 줄, 고령 보행자 커버리지 변화를 보여준다.
6. 근거: 시장 근처는 고령 이용이 실제로 많다(V6, 지하철 무임 비율). 효과 크기도 그대로 보여준다.
7. 한계: 보행시간 정의(현장 실측 V1로 확인한 범위), 보행속도 분포 가정(민감도), 기록 확인 필요 108곳.

## 7. 분석 방법과 검증 계획

검증 다섯 가지(V5는 선택)는 서로 다른 질문에 답한다. **결과가 기대와 다르게 나와도 그대로 보고한다.** 점검 우선순위 후보라는 표현을 쓰는 이유가 이것이다.

| 검증 | 묻는 것 | 방법 | 보고 지표 | 의미 |
| --- | --- | --- | --- | --- |
| V1 현장 실측 | 기록된 녹색신호시간이 실제와 맞는가, 점멸이 포함되는가 | (v2: 최소 5~10곳, #11) 부산 20\~30곳을 시군구·연장 구간별로 분산 선정, 보행신호 녹색 점등부터 종료까지 스톱워치로 측정(인도에서, 점멸 구간 분리 기록) | 기록값−실측값 차이(초)의 평균·분포 | 차이가 크면 전체 분석의 해석을 바꾸고, 필드 정의를 확정한다 |
| V2 속도 민감도 | 속도 가정이 바뀔 때 결과가 흔들리는가 | 1.0/0.8/0.7 간 읍면동 순위의 Spearman 상관, 상위 N의 중복률 | 상관계수, 중복 개수 | 중복이 낮으면 “우선순위”는 속도 가정에 많이 의존한다는 뜻 |
| V3 사고다발지역 연관성(연도 분할) | 후보가 실제 노인 보행사고와 같은 곳에 있는가 | 과거 연도 다발지역은 노출 플래그로, 최근 연도 다발지역은 확인용으로 분리한다. 후보와 최근 다발지역의 겹침 비율을 같은 시군구 안에서 섞은 무작위 추출(연장 구간 일치)과 비교한다(permutation) | 겹침 비율, 무작위 대비 배수, p값 | 겹침이 높아도 인과는 아니다(보행량·도로 규모 등). 낮아도 그대로 보고한다 |
| V4 축 독립성 · “이미 조정됐는가” | 부족이 고령 거주·목적지 노출과 어떤 관계인가 | (a) 읍면동 부족 비율과 65세 이상 비율의 Spearman 상관, 시도별·도시/농촌별로도 계산 (b) 경로당·시장 반경 안과 밖의 부족 비율 비교 | 상관계수, 안/밖 부족 비율 차이 | 음의 상관이거나 안쪽이 낮으면 이미 조정된 곳이 많다는 뜻이고, 오른쪽 위 칸이 비는 것 자체가 결과다. 양의 상관이면 지역 효과가 섞인 것을 의심한다 |
| V6 (v2) 시장 보정 근거 | 대형 시장 주변은 주민 구성과 별개로 고령 이용이 많은가 | 부산 지하철 역별 무임 승차 비율을 역 반경 주민 고령 비율로 회귀한 잔차를 시장 근처 역과 그 외로 비교(permutation), 점포 기준·반경·연도(2014~2024)·역 하나씩 빼기 민감도, 생활인구 방문인구 교차 확인 | 차이(%p), p값, 환산한 시장 보정값과 구간 | 2단계 계수의 근거. 무임에는 장애인·유공자가 섞여 있고 역 근처만 본다 |
| V7 (v2) 정책 반영 점검 | 노인보호구역 주변에 0.7m/s 기준이 반영됐는가 | 보호구역 300m 안 횡단보도 중 보행시간이 0.7m/s 기준식과 같은 곳의 비율을 어린이보호구역 150m 안·그 밖과 비교(현재 14% / 28% / 4.7%), 구별 분포. 미반영 곳과 사고다발지역 겹침(V3 방식) | 대상 수, 0.7식 수, 겹침 배수 | 보호구역 데이터는 점 좌표라 실제 구역과 다를 수 있다. 0.7이 의무인지 재량인지 확인 필요 |
| V5(선택) 보정 연관성 | 다른 요인을 통제해도 부족과 사고가 함께 움직이는가 | 읍면동 단위 로지스틱 회귀: 종속변수는 다발지역 포함 여부, 설명변수는 부족 비율·65세 이상 비율·평균 연장·시도 | 계수와 신뢰구간 | 통제한 연관성까지다. 보행량 데이터가 없어 인과는 아니다 |

**V1 실측은 게이트 A의 일부다.** 녹색신호시간 필드가 점멸을 포함하는지 확정하는 가장 빠른 방법이므로, 전체 파이프라인이 완성되기 전에 먼저 5\~10곳을 재다. 측정은 인도에서만 하고 차도에 들어가지 않는다.

**선택 검증:** 서울 123곳·제주 139곳·정부 1,000곳 목록을 구할 수 있으면 "우리 계산이 정부가 고른 곳을 얼마나 다시 찾는가"를 추가한다. 지금은 목록 공개 여부를 모른다.

**이 검증은 모두 연관성이다.** 인과 검증은 연장 지점의 전후 사고를 비교해야 하는데, 연장 대상 목록이 공개된 것을 못 찾았고 연장 후 기간도 짧아 11/3까지는 하지 않는다. 발표에서는 후속 과제로 말한다.

## 8. 기술 스펙

서버가 프론트 파일과 읽기 전용 API를 함께 제공하는 구조다. 계산은 파이프라인이 미리 끝내 두고, 서버는 결과 테이블을 조회해 내려주기만 한다. 데이터가 반기 갱신이고 쓰기 기능이 없으며, 최종 배포는 Ubuntu 서버(학과 클라우드)에 한다.

```text
입력 5종 → 파이프라인 → 결과 테이블 → [Ubuntu 서버: Nginx → API 서버 → DB] → 브라우저
```

원본 데이터는 서버에 올리지 않고, 파이프라인이 만든 결과 테이블만 DB에 적재한다. 같은 이유로 인증키와 원본은 서버 저장소에도 두지 않는다.

| 층 | 선택 | 비고 |
| --- | --- | --- |
| 파이프라인 | Python 3, pandas, geopandas(`sjoin`) | 결과를 DB 적재용 파일(GeoPackage 또는 Parquet)로 내보낸다 |
| 설정 | `config.yaml` 한 파일: 진입시간 7, 속도 \[1.0, 0.8, 0.7\], 표본 하한 5, 이상치 상한 80m·200s, 노출 반경 300m(200/500m 민감도) | 값을 바꾸고 재실행하면 전체 재현 |
| 서버 OS | Ubuntu LTS (22.04 또는 24.04) | 배포 대상 |
| 웹서버 | Nginx | 프론트 정적 파일 제공, `/api` 프록시, gzip, 경계 파일 캐시 |
| API 서버 | Python FastAPI (uvicorn) | 읽기 전용. 응답 스키마는 OpenAPI로 자동 생성되어 `contracts/`의 기준이 된다 |
| DB | PostgreSQL + PostGIS | 지역·영역 조회용. 서버가 작으면 SQLite로 낮출 수 있으나 공간 함수 차이를 주의 |
| 실행 방식 | Docker Compose (nginx, api, db) | 로컬과 서버가 같은 이미지. 학과 클라우드가 Docker를 막으면 apt와 systemd로 대체 |
| 프론트 | Vite 빌드, MapLibre GL JS, 사분면 산점도(D3 등) | 프레임워크는 담당자가 익숙한 것 |
| 배경 지도 | 미정 | 무료 타일의 라이선스·사용량 조건 미확인 |
| 출처 표기 | admdongkor(CC BY 4.0) 등 데이터 출처 | 지도 출처 표시(오른쪽 아래)와 About 탭 |

**API (모두 GET, 쓰기 없음)**

| 엔드포인트 | 용도 | 기능 |
| --- | --- | --- |
| `/api/areas?target=&radius=&sido=&sigungu=` | (v2) 읍면동별 평균 추가 초, 2초 이상 추가 수, 고령 보행자 커버리지, 65세 이상 비율, 사분면 값. `speed`는 하위 호환 | F5, F10, F22 |
| `/api/areas/{adm_cd}/crosswalks?speed=` | 지역별 횡단보도 목록 | F7 |
| `/api/crosswalks?target=&radius=&bbox=` | (v2) 전체 횡단보도 점: 단계·적용 속도·필요 시간·추가 초·이유·커버리지, 분석 제외·기록 확인 필요 포함 (C3 #73) | F19~F21 |
| `/api/crosswalks/candidates?bbox=&speed=&radius=` | (v1) 후보 횡단보도 점 레이어 | F5, F11 |
| `/api/validation` | V1~V7 결과 | F8 |
| `/api/meta` | 기준월, 좌표 커버리지, 필드 정의 상태, 출처, (v2) 계수와 근거 `coefficients` | F9, F23 |
| `/api/export/{areas\|crosswalks}.csv` | 결과 내려받기 | F12 |
| `/healthz` | 상태 확인 | F16 |

- 목표 커버리지 3종(v2)과 속도 3종(v1)은 파이프라인이 미리 계산해 두므로, 화면에서 바꾸면 `target`·`speed` 값만 바꿔 다시 조회한다. 서버는 요청마다 계산하지 않는다.
- 읍면동 경계 도형은 API가 아니라 단순화·gzip한 정적 파일로 제공한다(전국 원본이 약 35MB). 속도를 바꿀 때는 경계를 다시 받지 않고 값만 받는다.
- 오류 응답은 서버 내부 정보를 노출하지 않고, 쓰기 메서드는 거부한다.

**개발·배포 환경**

| 환경 | 용도 | 주소 | 데이터 |
| --- | --- | --- | --- |
| local | 각자 PC에서 개발 | `localhost` | 작은 샘플(부산 일부) |
| server-dev (선택) | 팀 통합 확인 | 학과 클라우드 임시 주소 | 부산 전체 |
| prod | 발표·제출 | 최종 URL | 전국 |

- 로컬은 프론트 개발 서버(:5173)가 `/api` 요청을 API(:8000)로 프록시하고, API는 로컬 DB 컨테이너(:5432)를 읽는다. 브라우저에서는 같은 주소로 보이므로 CORS 문제가 로컬과 운영에서 똑같이 사라진다. DB와 API는 `docker compose up` 한 번으로 띄운다.
- 환경 차이는 `.env.local`과 `.env.prod`의 값(DB 접속 정보, 허용 주소)으로만 둔다. 저장소에는 `.env.example`만 올린다.
- 팀원은 전국 데이터를 받을 필요 없이, 작은 샘플 적재 스크립트로 같은 형태의 데이터를 로컬 DB에 넣는다.
- API가 아직 없을 때는 mock 모드(F17, P1)로 `contracts/samples/`의 JSON을 읽어 프론트만 개발한다. 서버 담당이 늦어져도 웹 개발이 막히지 않게 하는 장치다.
- 서버가 열리기 전에는 로컬 Ubuntu(WSL 또는 가상머신)에서 먼저 확인하고, 서버가 열리면 같은 이미지로 옮긴다.

**되돌리기 어려운 결정은 지금 고정한다.** 저장 좌표계는 EPSG:4326이고 거리·겹침 계산은 EPSG:5179로 변환해서 한다. 읍면동 코드 `adm_cd`는 항상 문자열로 다뤄 앞자리 0이 사라지지 않게 하며, API 응답에서도 같다. 나머지는 바꾸어도 비용이 작다.

## 9. 데이터 모델

## 10. 화면 구성

화면은 두 개다. 메인 화면에서 데모가 끝나고, 검증 화면은 근거를 보여주는 용도다.

| 화면 | 구성 | 상호작용 |
| --- | --- | --- |
| 메인 | 왼쪽 지도(MapLibre, 읍면동 채색)와 후보 횡단보도 점 레이어 토글, 오른쪽 위 사분면 차트, 오른쪽 아래 상위 N 목록, 상단 속도 슬라이더(0.7/0.8/1.0), 헤더 About 탭(한계·출처) | 슬라이더 변경 → 세 영역 동시 갱신, 사분면 점·목록 행·지도 폴리곤 클릭 시 연동 강조 |
| 지역 상세 패널 | 읍면동 이름, 65세 이상 비율, 분석 횡단보도 수, 부족 건수·비율·평균 부족 초, 횡단보도 목록(연장·기록·필요·부족 초, 노출 플래그: 경로당·시장·보호구역·사고다발지역) | 목록 행 클릭 → 지도에서 해당 점으로 이동 |
| 검증 | V1 실측 비교 표와 산점도, V2 순위 상관 표, V3 겹침 비율과 무작위 분포, V4 상관과 안/밖 비교, V5 회귀 계수 | 지도 아래 탭으로 전환 |

**v2 화면 (새 탭이 아니라 같은 자리 교체):** 상단 속도 슬라이더 → "기록값 / 3단계 기준" 전환과 목표 커버리지 85·90·95%. 읍면동 채색 → 2초 이상 추가 비율. 후보 점 → 모든 횡단보도 점(색 = 단계, 크기 = 추가 초, 기록 확인 필요는 속 빈 회색). 점 클릭 → 정보 카드(기록 → 기준 적용 시간, 이유 한 줄, 커버리지). 상위 N 지역 → 횡단보도 우선순위. 검증 화면에 V6·V7 카드, 속도 3종 비교는 V2 카드로 이동.

**서버 응답 상태:** API를 쓰므로 모든 화면에 로딩 표시와 오류 표시(다시 시도 버튼)를 둔다. 속도 슬라이더를 연속으로 움직여도 마지막 값의 응답만 반영한다.

공통 규칙은 세 가지다. 표시는 항상 "점검 우선순위 후보"라는 말로 하고, 표본이 적은(`low_sample`) 읍면동은 회색 처리하며, 색은 단일 색 계열의 명도로 나타내 색맹에서도 읽히게 한다. 모바일 세로 화면 최적화는 MVP에서 둔다(발표는 데스크톱 화면).

## 12. 리스크, 열린 이슈, 성공 기준

가장 큰 리스크는 녹색신호시간 필드의 의미를 모른 채 결과를 "부족"이라 부르는 것이다. 이 한 가지가 무너지면 나머지 결과 전체가 의미를 잃는다.
