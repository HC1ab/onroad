# 한 박자 — 횡단보도 초록불 시간 전수 점검 PRD

Oct 19, 2026 · @SH

전국 횡단보도의 기록된 초록불 시간을 기준식 필요시간과 전수 비교하고, 고령 거주 비율과 목적지·사고 노출을 겹쳐 점검이 필요한 지역과 횡단보도 후보를 찾는 웹 서비스다. 팀 길건너친구들(안), 프로젝트명 "한 박자"(영문안 GreenGap).

## 1. 배경과 문제 정의

보행 신호 시간의 기준은 진입 7초에 연장 1m당 1초(1m/s)를 더한 값이다. 노인보호구역이나 고령자가 많은 곳에는 0.7\~0.8m/s를 적용하는 지침이 있다(서울시 0.8, 경찰·제주·국토부 0.7). 문제는 이 기준을 전국 모든 횡단보도에 적용해 본 점검이 눈에 띄지 않는다는 점이다.

**선행 사례는 모두 선정된 일부 지점의 개선이다.** 아래 수치는 이전 조사 기록 기준이며, 발표 자료에 넣기 전 원문 재확인이 필요하다.

- 국토부·경찰청(2025-05-15): 전통시장·병원 인근 1,000곳을 1m/s에서 0.7m/s로 조정, 자동연장 시스템 221곳
- 서울시(2024-10): 비보호 횡단보도 123곳, 동별 고령자 비율과 10년 사고 기준 선정, 3\~6초 연장
- 제주(2025): 139곳을 0.7m/s로 점검, 99곳 평균 4.8초 연장
- 부산(2018): 111곳, 2\~3초 연장
- 노인보호구역은 고령자 1만 명당 2.2곳으로 어린이(21.5곳)보다 적고, 노인 보행사고의 98%가 보호구역 밖에서 난다는 기록이 있다(2023, 원문 재확인 필요)

**차별점 한 문장:** 우리가 찾은 범위에서는 전국 횡단보도 전수에 대해 부족 초수를 계산하고 고령 거주 비율과 목적지·사고 노출을 겹쳐 점검 우선 지역을 보여준 사례를 찾지 못했다. 이는 "못 찾았다"일 뿐 "없다"는 증명이 아니다.

**목적지 기준은 정부도 이미 썼다.** 국토부·경찰청은 전통시장·병원 인근을, 서울시는 동별 고령자 비율과 사고를 기준으로 골랐다(위 사례, 원문 재확인 필요). 거주나 목적지 기준 자체는 차별점이 아니다. 차별점은 같은 기준으로 전국을 전수 계산해 **아직 부족한 곳이 남아 있는지** 확인하는 것이다. "이미 조정됐을 것"이라는 가설도 V4(7장)로 직접 확인한다.

**하지 않기로 한 것:** 고령화를 예측해 미리 늘린다는 접근은 뺐다. 지금 이미 부족한 곳이 있는지가 먼저이고, 시군구 이하 단위의 장래인구추계가 있는지 확인하지 못했다.

## 2. 목표와 범위

MVP의 목표는 **"전국 전수 계산 → 속도별 부족 초수 → 고령 비율 사분면 → 검증 결과"를 URL 하나로 보여주는 것**이다.

**목표**

- 전국 횡단보도 각각에 대해 필요시간(7 + L/v)과 기록된 녹색신호시간을 비교해 부족 여부와 부족 초수를 구한다 (v = 1.0 / 0.8 / 0.7m/s).
- 읍면동 단위로 부족 비율과 65세 이상 인구 비율을 2축 사분면에 배치하고, 횡단보도 단위로 목적지·사고 노출 플래그(경로당·전통시장·보호구역·사고다발지역)를 붙여 "점검 우선순위 후보" 지역을 찾는다.
- 결과를 검증한다: 부산 현장 실측, 속도 민감도, 노인 보행사고 다발지역과의 연관성(연도 분할), 두 축의 독립성(V4).
- 11/3까지 Ubuntu 서버에 배포해 URL로 접속 가능한 상태로 만든다 (서버가 프론트 파일과 읽기 전용 API를 함께 제공한다).

**비목표**

- 고령화 예측, 신호 연장 효과나 교통 영향 시뮬레이션
- 개별 횡단보도를 "위험"이나 "위반"으로 단정하는 표현
- 로그인, 사용자 입력 저장(쓰기 API 없음), 실시간 데이터 연동, LLM 해설
- 신호 시간 변경 권고안 자동 생성

**절반만 만들면 남는 것:** 사분면 지도와 상위 N 목록까지만 완성해도 "전수 계산 + 고령 비율"이라는 핵심은 남는다. 검증(P0 아래쪽)이 빠지면 근거가 약해지므로 컷 라인은 기능이 아니라 검증 쪽에서 치지 않는다.

## 3. 핵심 산식과 표현 원칙

모든 판정은 아래 한 식에서 나오고, 속도 v만 바꿔 세 번 계산한다.

```latex
T_{need}(v) = 7 + \frac{L}{v}, \qquad \text{gap}(v) = T_{need}(v) - G_{rec}
```

L은 횡단보도연장(m), G\_rec는 기록된 녹색신호시간(s)이다. gap이 0보다 크면 그 속도 기준에서 "기록값이 기준식보다 짧음"으로 표시한다.

| 속도 v | 의미 | 근거 |
| --- | --- | --- |
| 1.0m/s | 일반 기준 | 신호 설치 기준(진입 7초 + 1초/m) |
| 0.8m/s | 보행약자 기준(서울시) | 서울시 안내 페이지 |
| 0.7m/s | 노인 기준(경찰·제주·국토부) | 경찰·제주·국토부 발표 |

**노출 두 층(수정):** 거주 노출은 읍면동 65세 이상 비율이고, 목적지 노출은 횡단보도 반경 N m 안에 경로당·전통시장·노인보호구역이 있는지, 사고다발지역(과거 연도) 안인지다. 기본 반경은 300m이고 200/500m로 민감도를 본다. 300m는 임의값이다. 병원은 좌표 필드를 확인한 뒤 추가한다(P2).

**사분면(거주 노출 기준, 초안):** 가로축은 읍면동 안에서 분석 가능한 횡단보도 중 gap > 0인 비율, 세로축은 65세 이상 인구 비율이다. 가중합 점수는 만들지 않는다. 경계선 기본값은 전국 중앙값이고 화면에서 조절할 수 있게 한다. 오른쪽 위 칸이 “점검 우선순위 후보” 지역이다.

**후보 횡단보도 정의(신규):** 어느 속도 기준에서든 gap > 0이면서 목적지·사고 노출 플래그가 1개 이상인 횡단보도다. 우선순위는 해당하는 노출의 개수와 종류로 정하고 가중합 점수는 만들지 않는다. 거주 비율이 낮아도 목적지 노출로 잡힐 수 있다. 플래그가 없다는 것은 노출이 없다는 뜻이 아니다(시설 데이터 누락 가능).

**표본 하한(초안):** 읍면동 안의 분석 가능 횡단보도가 5곳 미만이면 사분면에서 회색으로 표시하고 순위에서 뺀다. 5는 임의값이며 데이터 분포를 본 뒤 조정한다.

**표현 원칙**

- 허용: “점검 우선순위 후보”, “기록값이 기준식보다 짧음”
- 금지: “위험”, “위반”, “불법”, “시간을 늘려야 한다”는 단정
- 이 도구는 인과를 주장하지 않는다. 부족 판정과 노출, 사고의 “겹침·연관”까지만 말하고 “\~ 때문에 위험”이나 “늘리면 사고가 준다”는 쓰지 않는다
- 읍면동 평균은 그 동의 개별 횡단보도 이용자 구성을 뜻하지 않는다(생태학적 오류). 지도 하단에 한 줄로 항상 표시한다.
- 녹색신호시간 필드가 점멸 시간을 포함하는지 확인하기 전에는 결과를 “부족”으로 부르지 않는다(4장 게이트).

**제외한 것:** 장래인구추계(시군구 단위 제공 여부 미확인), 연령별 유동인구(전국·읍면동 단위는 못 찾았고 경기도 시군구 단위만 확인), 노인복지관 위치(전국 단위 데이터를 못 찾음). 서울 123곳·제주 139곳·정부 1,000곳의 대상 목록은 공개된 것을 못 찾아 “정답 대조” 검증은 목록을 구할 수 있을 때만 한다.

**게이트 (통과 못 하면 여기서 멈춘다)**

1. 게이트 A — 횡단보도 CSV: 부산 행 수, 연장·녹색신호시간·좌표 입력률을 확인한다(`check_crosswalk_data.py`). 일반 기준(1.0m/s)에서 부족이 40% 초과면 필드 정의 문제(점멸 제외 등), 1% 미만이면 자동 입력 의심으로 보고 원문 정의를 확인한다.
2. 게이트 B — 65세 이상 인구: 전국 읍면동이 한 파일에 들어 있는지, 총인구 필드가 있는지 확인한다.
3. 게이트 C — 코드 결합: 경계 파일과 인구 파일의 읍면동 코드 일치율을 측정한다. 일치율이 낮으면 이름+시군구 매칭이나 경계 기준일 맞추기를 적용한다(2026-07-01 시도·시군구 코드 개편 주의).
4. 게이트 D(선택) — 노출 데이터: 경로당·전통시장 좌표 입력률과 전국 누락 정도, 사고다발지역 API의 연도 범위를 확인한다. 통과하지 못해도 MVP는 사고다발지역·보호구역 플래그와 읍면동 축으로 진행한다.

횡단보도 데이터에는 읍면동 정보가 없고 시도·시군구와 좌표뿐이다. 그래서 좌표로 공간 조인을 해야 하고, 좌표 입력률이 결과의 커버리지를 정한다.

## 5. 사용자와 시나리오

주 사용자는 발표 현장의 심사위원이고, 실제 활용 관점의 사용자는 지자체 교통안전 담당자다. MVP는 두 사용자가 같은 화면을 쓰도록 만든다.

| 사용자 | 알고 싶은 것 | 화면에서 보는 것 |
| --- | --- | --- |
| 심사위원 | 이 분석이 맞는가, 신뢰할 수 있는가 | 전국 지도, 속도 슬라이더, 검증 결과 페이지 |
| 지자체 담당자 | 우리 관할에서 먼저 볼 곳이 어디인가 | 시군구 필터, 상위 N 목록, 개별 횡단보도 좌표·부족 초수 |
| 시민(보조) | 우리 동네는 어떤가 | 읍면동 상세 카드 |

**발표 데모 흐름 (약 3분 기준, 확정 전 초안)**

1. 전국 지도에서 읍면동 채색지도로 “우리나라에서 기록값이 기준식보다 짧은 횡단보도가 많은 곳”을 보여준다.
2. 속도 슬라이더를 1.0 → 0.8 → 0.7로 옮기며 지도가 어떻게 변하는지 보여준다(민감도).
3. 사분면 차트로 “부족 비율 높음 × 고령 비율 높음” 칸의 지역을 고른다.
4. 거주 비율이 낮아도 경로당·전통시장·보호구역·사고다발지역 반경에 걸리는 후보 횡단보도를 점 레이어로 켜서 보여준다.
5. 한 지역을 클릭해 상위 횡단보도 목록(연장, 기록 초, 필요 초, 부족 초, 노출 플래그)을 보여준다.
6. 검증 페이지에서 부산 현장 실측, 사고다발지역 연관성(연도 분할), 그리고 “이미 조정됐는가”(시장·경로당 반경 안과 밖의 부족 비율 비교) 결과를 보여준다.
7. 한계를 스스로 밝힌다(필드 정의, 읍면동 평균의 한계, 인과 미검증).

## 7. 분석 방법과 검증 계획

검증 다섯 가지(V5는 선택)는 서로 다른 질문에 답한다. **결과가 기대와 다르게 나와도 그대로 보고한다.** 점검 우선순위 후보라는 표현을 쓰는 이유가 이것이다.

| 검증 | 묻는 것 | 방법 | 보고 지표 | 의미 |
| --- | --- | --- | --- | --- |
| V1 현장 실측 | 기록된 녹색신호시간이 실제와 맞는가, 점멸이 포함되는가 | 부산 20\~30곳을 시군구·연장 구간별로 분산 선정, 보행신호 녹색 점등부터 종료까지 스톱워치로 측정(인도에서, 점멸 구간 분리 기록) | 기록값−실측값 차이(초)의 평균·분포 | 차이가 크면 전체 분석의 해석을 바꾸고, 필드 정의를 확정한다 |
| V2 속도 민감도 | 속도 가정이 바뀔 때 결과가 흔들리는가 | 1.0/0.8/0.7 간 읍면동 순위의 Spearman 상관, 상위 N의 중복률 | 상관계수, 중복 개수 | 중복이 낮으면 “우선순위”는 속도 가정에 많이 의존한다는 뜻 |
| V3 사고다발지역 연관성(연도 분할) | 후보가 실제 노인 보행사고와 같은 곳에 있는가 | 과거 연도 다발지역은 노출 플래그로, 최근 연도 다발지역은 확인용으로 분리한다. 후보와 최근 다발지역의 겹침 비율을 같은 시군구 안에서 섞은 무작위 추출(연장 구간 일치)과 비교한다(permutation) | 겹침 비율, 무작위 대비 배수, p값 | 겹침이 높아도 인과는 아니다(보행량·도로 규모 등). 낮아도 그대로 보고한다 |
| V4 축 독립성 · “이미 조정됐는가” | 부족이 고령 거주·목적지 노출과 어떤 관계인가 | (a) 읍면동 부족 비율과 65세 이상 비율의 Spearman 상관, 시도별·도시/농촌별로도 계산 (b) 경로당·시장 반경 안과 밖의 부족 비율 비교 | 상관계수, 안/밖 부족 비율 차이 | 음의 상관이거나 안쪽이 낮으면 이미 조정된 곳이 많다는 뜻이고, 오른쪽 위 칸이 비는 것 자체가 결과다. 양의 상관이면 지역 효과가 섞인 것을 의심한다 |
| V5(선택) 보정 연관성 | 다른 요인을 통제해도 부족과 사고가 함께 움직이는가 | 읍면동 단위 로지스틱 회귀: 종속변수는 다발지역 포함 여부, 설명변수는 부족 비율·65세 이상 비율·평균 연장·시도 | 계수와 신뢰구간 | 통제한 연관성까지다. 보행량 데이터가 없어 인과는 아니다 |

**V1 실측은 게이트 A의 일부다.** 녹색신호시간 필드가 점멸을 포함하는지 확정하는 가장 빠른 방법이므로, 전체 파이프라인이 완성되기 전에 먼저 5\~10곳을 재다. 측정은 인도에서만 하고 차도에 들어가지 않는다.

**선택 검증:** 서울 123곳·제주 139곳·정부 1,000곳 목록을 구할 수 있으면 "우리 계산이 정부가 고른 곳을 얼마나 다시 찾는가"를 추가한다. 지금은 목록 공개 여부를 모른다.

**이 검증은 모두 연관성이다.** 인과 검증은 연장 지점의 전후 사고를 비교해야 하는데, 연장 대상 목록이 공개된 것을 못 찾았고 연장 후 기간도 짧아 11/3까지는 하지 않는다. 발표에서는 후속 과제로 말한다.

## 8. 기술 스펙

서버가 프론트 파일과 읽기 전용 API를 함께 제공하는 구조다. 계산은 파이프라인이 미리 끝내 두고, 서버는 결과 테이블을 조회해 내려주기만 한다. 데이터가 반기 갱신이고 쓰기 기능이 없으며, 최종 배포는 Ubuntu 서버(학과 클라우드)에 한다.

```text
입력 5종 → 파이프라인 → 결과 테이블 → [Ubuntu 서버: Nginx → API 서버 → DB] → 브라우저
```

원본 데이터는 서버에 올리지 않고, 파이프라인이 만든 결과 테이블만 DB에 적재한다. 같은 이유로 인증키와 원본은 서버 저장소에도 두지 않는다.

| 층 | 선택 | 비고 |
| --- | --- | --- |
| 파이프라인 | Python 3, pandas, geopandas(`sjoin`) | 결과를 DB 적재용 파일(GeoPackage 또는 Parquet)로 내보낸다 |
| 설정 | `config.yaml` 한 파일: 진입시간 7, 속도 \[1.0, 0.8, 0.7\], 표본 하한 5, 이상치 상한 80m·200s, 노출 반경 300m(200/500m 민감도) | 값을 바꾸고 재실행하면 전체 재현 |
| 서버 OS | Ubuntu LTS (22.04 또는 24.04) | 배포 대상 |
| 웹서버 | Nginx | 프론트 정적 파일 제공, `/api` 프록시, gzip, 경계 파일 캐시 |
| API 서버 | Python FastAPI (uvicorn) | 읽기 전용. 응답 스키마는 OpenAPI로 자동 생성되어 `contracts/`의 기준이 된다 |
| DB | PostgreSQL + PostGIS | 지역·영역 조회용. 서버가 작으면 SQLite로 낮출 수 있으나 공간 함수 차이를 주의 |
| 실행 방식 | Docker Compose (nginx, api, db) | 로컬과 서버가 같은 이미지. 학과 클라우드가 Docker를 막으면 apt와 systemd로 대체 |
| 프론트 | Vite 빌드, MapLibre GL JS, 사분면 산점도(D3 등) | 프레임워크는 담당자가 익숙한 것 |
| 배경 지도 | 미정 | 무료 타일의 라이선스·사용량 조건 미확인 |
| 출처 표기 | admdongkor(CC BY 4.0) 등 데이터 출처 | 화면 하단 푸터 |

**API (모두 GET, 쓰기 없음)**

| 엔드포인트 | 용도 | 기능 |
| --- | --- | --- |
| `/api/areas?speed=&sido=&sigungu=` | 읍면동별 짧음 비율, 65세 이상 비율, 사분면 값 | F5, F6, F10 |
| `/api/areas/{adm_cd}/crosswalks?speed=` | 지역별 횡단보도 목록 | F7 |
| `/api/crosswalks/candidates?bbox=&speed=&radius=` | 후보 횡단보도 점 레이어 | F5, F11 |
| `/api/validation` | V1~V5 결과 | F8 |
| `/api/meta` | 기준월, 좌표 커버리지, 필드 정의 상태, 출처 | F9 |
| `/api/export/{areas\|crosswalks}.csv` | 결과 내려받기 | F12 |
| `/healthz` | 상태 확인 | F16 |

- 속도 3종은 파이프라인이 미리 계산해 두므로, 슬라이더를 움직이면 `speed` 값만 바꿔 다시 조회한다. 서버는 요청마다 계산하지 않는다.
- 읍면동 경계 도형은 API가 아니라 단순화·gzip한 정적 파일로 제공한다(전국 원본이 약 35MB). 속도를 바꿀 때는 경계를 다시 받지 않고 값만 받는다.
- 오류 응답은 서버 내부 정보를 노출하지 않고, 쓰기 메서드는 거부한다.

**개발·배포 환경**

| 환경 | 용도 | 주소 | 데이터 |
| --- | --- | --- | --- |
| local | 각자 PC에서 개발 | `localhost` | 작은 샘플(부산 일부) |
| server-dev (선택) | 팀 통합 확인 | 학과 클라우드 임시 주소 | 부산 전체 |
| prod | 발표·제출 | 최종 URL | 전국 |

- 로컬은 프론트 개발 서버(:5173)가 `/api` 요청을 API(:8000)로 프록시하고, API는 로컬 DB 컨테이너(:5432)를 읽는다. 브라우저에서는 같은 주소로 보이므로 CORS 문제가 로컬과 운영에서 똑같이 사라진다. DB와 API는 `docker compose up` 한 번으로 띄운다.
- 환경 차이는 `.env.local`과 `.env.prod`의 값(DB 접속 정보, 허용 주소)으로만 둔다. 저장소에는 `.env.example`만 올린다.
- 팀원은 전국 데이터를 받을 필요 없이, 작은 샘플 적재 스크립트로 같은 형태의 데이터를 로컬 DB에 넣는다.
- API가 아직 없을 때는 mock 모드(F17, P1)로 `contracts/samples/`의 JSON을 읽어 프론트만 개발한다. 서버 담당이 늦어져도 웹 개발이 막히지 않게 하는 장치다.
- 서버가 열리기 전에는 로컬 Ubuntu(WSL 또는 가상머신)에서 먼저 확인하고, 서버가 열리면 같은 이미지로 옮긴다.

**되돌리기 어려운 결정은 지금 고정한다.** 저장 좌표계는 EPSG:4326이고 거리·겹침 계산은 EPSG:5179로 변환해서 한다. 읍면동 코드 `adm_cd`는 항상 문자열로 다뤄 앞자리 0이 사라지지 않게 하며, API 응답에서도 같다. 나머지는 바꾸어도 비용이 작다.

| `admin_area` | 읍면동 경계 | `adm_cd`, `adm_name`, `sido`, `sigungu`, `geometry` |
| `pop_age` | 읍면동 인구 | `adm_cd`, `pop_total`, `pop_65plus`, `ratio_65plus`, `ref_month` |
| `crash_zone` | 노인 보행사고 다발지역 (과거·최근 연도 분리) | `zone_id`, `year`, `accident_cnt`, `death_cnt`, `geometry` |
| `facility_poi` | 목적지 노출 시설 | `poi_id`, `kind`(경로당/전통시장/병원/보호구역), `name`, `lat`, `lon`, `source`, `ref_date` |
| `crosswalk_gap` | 횡단보도별 속도별 판정 | `cw_id`, `speed_mps`, `t_need_s`, `gap_s`, `is_short`(gap>0), `is_candidate`(is\_short 그리고 exposure\_cnt≥1) |
| `area_vulnerability` | 읍면동별 속도별 집계 | `adm_cd`, `speed_mps`, `n_analyzed`, `n_short`, `short_ratio`, `mean_gap_s`, `ratio_65plus`, `quadrant`, `n_candidate`, `low_sample`(n<5) |
| `field_audit` | 현장 실측 | `cw_id`, `measured_green_s`, `measured_flash_s`, `diff_s`, `measured_at`, `note` |
| `meta` | 서버가 보여줄 기준 정보 | `ref_month`(인구 기준 월), `coverage_ratio`(좌표 커버리지), `green_def_status`(녹색신호시간 정의 확정 여부), `built_at`, `sources` |

**서버 DB에 적재하는 테이블:** `crosswalk`(제외 건 제외), `crosswalk_gap`, `area_vulnerability`, `admin_area`(경계 제외 속성), `field_audit`, `meta`, 검증 결과(V1~V5 수치). 후보 횡단보도 점 레이어는 어느 속도에서라도 gap>0인 행만 조회하도록 인덱스를 둔다.

**정적 파일:** 읍면동 경계 도형(단순화·gzip)만 서버가 정적으로 제공한다. 이외 값은 모두 API로 조회한다. F18(정적 폴백)을 위해 같은 결과를 JSON·GeoJSON 묶음으로 내보내는 기능을 둔다.

## 10. 화면 구성

화면은 두 개다. 메인 화면에서 데모가 끝나고, 검증 화면은 근거를 보여주는 용도다.

| 화면 | 구성 | 상호작용 |
| --- | --- | --- |
| 메인 | 왼쪽 지도(MapLibre, 읍면동 채색)와 후보 횡단보도 점 레이어 토글, 오른쪽 위 사분면 차트, 오른쪽 아래 상위 N 목록, 상단 속도 슬라이더(0.7/0.8/1.0), 하단 한계 한 줄 | 슬라이더 변경 → 세 영역 동시 갱신, 사분면 점·목록 행·지도 폴리곤 클릭 시 연동 강조 |
| 지역 상세 패널 | 읍면동 이름, 65세 이상 비율, 분석 횡단보도 수, 부족 건수·비율·평균 부족 초, 횡단보도 목록(연장·기록·필요·부족 초, 노출 플래그: 경로당·시장·보호구역·사고다발지역) | 목록 행 클릭 → 지도에서 해당 점으로 이동 |
| 검증 | V1 실측 비교 표와 산점도, V2 순위 상관 표, V3 겹침 비율과 무작위 분포, V4 상관과 안/밖 비교, V5 회귀 계수 | 지도 아래 탭으로 전환 |

**서버 응답 상태:** API를 쓰므로 모든 화면에 로딩 표시와 오류 표시(다시 시도 버튼)를 둔다. 속도 슬라이더를 연속으로 움직여도 마지막 값의 응답만 반영한다.

공통 규칙은 세 가지다. 표시는 항상 "점검 우선순위 후보"라는 말로 하고, 표본이 적은(`low_sample`) 읍면동은 회색 처리하며, 색은 단일 색 계열의 명도로 나타내 색맹에서도 읽히게 한다. 모바일 세로 화면 최적화는 MVP에서 둔다(발표는 데스크톱 화면).

## 12. 리스크, 열린 이슈, 성공 기준

가장 큰 리스크는 녹색신호시간 필드의 의미를 모른 채 결과를 "부족"이라 부르는 것이다. 이 한 가지가 무너지면 나머지 결과 전체가 의미를 잃는다.

| 리스크 | 대응 |
| --- | --- |
| 녹색신호시간 정의·단위 불명 | 게이트 A + V1 실측을 가장 먼저 실행, 확정 전에는 “부족” 표현 금지 |
| 경계·인구 코드 불일치 | 게이트 C, 이름+시군구 매칭 대체, 미매칭 목록 공개 |
| 좌표 결측·오류로 커버리지 하락 | 입력률과 제외 건수를 화면에 공개, 커버리지 낮은 지역은 회색 |
| 시험 기간(10/20\~22, 10/26) 작업 중단 | 시험 전에 파이프라인 P0(F1\~F4)를 끝내고, 시험 중에는 프론트 작업만 |
| “배포” 요건 해석 차이 | 서버 배포로 URL 접속을 만족시키되, 규정 문구 확인 필요 |
| 발표 현장 네트워크·서버 장애 | 같은 결과를 정적 파일로 내보내는 폴백(F18)을 준비해 서버 없이도 데모한다 |
| 학과 클라우드 사양·접근 시점 불확실 | 로컬 Docker(와 필요 시 WSL·가상머신 Ubuntu)에서 먼저 개발하고, 서버가 열리면 같은 이미지로 옮긴다 |
| 로컬에서는 되는데 서버에서 안 됨 | 같은 Docker 이미지를 쓰고, 환경 차이는 `.env` 값으로만 둔다 |
| 공개 서버 보안 | 읽기 전용 API, DB는 외부에서 접근 차단, 비밀번호는 `.env`, 요청 횟수 제한. 서버에 원본 데이터와 인증키를 두지 않는다 |
| 서버 추가로 작업량 증가 | 최소 서버를 P0로 먼저 통과시키고 나머지 엔드포인트와 폴백은 이후에 붙인다 |
| 읍면동 평균의 한계(생태학적 오류) | 화면에 항상 고지, 횡단보도 단위 목록을 함께 제공 |
| 연관성이 인과로 읽힘 | 표현 원칙(3장)을 고정하고, 발표에서 “인과는 확인하지 않았고 점검 순서를 정하는 도구”라고 직접 말한다 |
| 노출 데이터 누락(경로당 등 지자체 등록 기반) | 시설 좌표 결측 건수를 공개하고 “플래그 없음은 노출 없음이 아니다”를 화면에 적는다 |
| 사고 데이터로 고르고 같은 데이터로 검증하는 순환 | 연도 분할(과거 연도 = 플래그, 최근 연도 = 확인). 연도 범위가 안 되면 사고다발지역을 확인용으로만 쓴다 |
