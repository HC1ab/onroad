1. 왜 하나 — 문제 정의

고령자에게 초록불은 짧다

나이가 들면 걷는 속도가 느려지고, 건너기 시작하는 데도 시간이 더 걸립니다. 같은 횡단보도라도 고령자는 초록불 안에 다 건너지 못하고, 건너는 중에 신호가 바뀌기 쉽습니다.

이것은 사고로 이어질 수 있다

길 한가운데서 신호가 바뀌면 차량과 보행자가 같은 공간에 남게 됩니다. 실제로 2024년 보행 중 교통사고 사망자 920명 가운데 65세 이상이 616명(약 67%)이었고, 그중 절반 이상(346명, 56.2%)이 길을 건너던 중에 일어났다고 보도되었습니다(한국교통안전공단 자료 인용 기사). 노인 보행사고를 줄이려면 사고가 난 뒤에 고치는 것이 아니라, 초록불이 짧은 곳을 미리 찾아 살펴보는 것이 필요합니다.

기준은 있지만, 전국에 적용해 본 적은 없다

보행 신호 시간은 진입 7초 + 횡단 거리 1m당 1초(보행 속도 1.0m/s)로 정하고, 고령자를 위해 0.8m/s(서울시)나 0.7m/s(경찰·제주·국토부)를 적용하라는 지침도 있습니다. 하지만 지금까지의 개선은 기관이 고른 일부 지점(수십~1,000곳)에 대한 것이었습니다. 노인 보행사고의 대부분이 노인보호구역 밖에서 난다는 기록도 있어, 골라서 고치는 방식으로는 놓치는 곳이 생길 수 있습니다.

우리의 핵심: 늘릴지 판단할 수 있는 데이터를 만든다

초록불을 몇 초 늘릴지, 어디부터 손볼지는 지자체와 경찰이 정합니다. 그 판단을 하려면 "어디가 기준보다 짧게 기록되어 있고, 그곳에 고령자가 얼마나 지나는가"를 한눈에 볼 수 있어야 합니다. 한 박자는 이 판단에 필요한 데이터를 만듭니다.

  1. 너무 짧은 횡단보도를 찾는다. 전국 횡단보도 전부에 기준식을 적용해, 기록된 초록불이 필요한 시간보다 몇 초 짧은지 계산합니다(속도 1.0·0.8·0.7 세 기준).
  2. 고령자가 많이 지나는 곳을 겹친다. 고령화가 많이 진행된 읍면동(65세 이상 비율), 경로당·전통시장·보호구역 주변, 노인 보행사고 다발지역을 함께 표시합니다.
  3. 우선순위로 정리한다. 짧음 비율과 고령 비율이 모두 높은 지역, 노출이 겹친 횡단보도를 "점검 우선순위 후보"로 보여주고, 횡단보도별로 몇 초가 짧은지까지 내려가 볼 수 있게 합니다.
  4. 근거를 검증한다. 현장 실측, 속도 기준을 바꿨을 때의 변화, 사고다발지역과의 겹침, "이미 조정되어 있는가"를 확인해 함께 공개합니다.
우리가 하지 않는 것: 개별 횡단보도를 "위험"하거나 "위반"이라고 판정하지 않습니다. 후보를 보여주고 판단은 담당 기관이 합니다. 초록불을 늘리면 사고가 준다고 주장하지도 않습니다. 데이터가 보여주는 것은 겹침과 연관까지입니다.

2. 무엇을 만드나

모든 판정은 아래 식 하나에서 나옵니다. 속도 v만 바꿔 세 번 계산합니다.

필요시간 = 7 + 연장 ÷ v  ·  gap = 필요시간 − 기록된 녹색신호시간
속도 v의미근거
1.0 m/s일반 기준신호 설치 기준
0.8 m/s보행약자서울시 안내
0.7 m/s노인경찰·제주·국토부

gap > 0이면 "기록값이 기준식보다 짧음"으로 표시합니다. 그 위에 두 가지 노출을 겹칩니다.

거주 노출

읍면동별 65세 이상 인구 비율. 짧음 비율과 함께 2축 사분면을 만들고, 오른쪽 위 칸이 "점검 우선순위 후보" 지역입니다.

목적지·사고 노출

횡단보도 반경 300m 안에 경로당·전통시장·노인보호구역이 있는지, 노인 보행사고 다발지역 안인지. 하나라도 걸리면 "후보 횡단보도"입니다.

검증

V1 현장 실측, V2 속도 민감도, V3 사고다발지역 연관성(연도 분할), V4 이미 조정됐는가. 결과가 기대와 달라도 그대로 보여줍니다.

결과물은 URL 하나로 접속하는 웹 지도입니다: 읍면동 채색지도, 속도 슬라이더, 사분면 차트, 상위 N 지역 목록, 지역 상세, 검증 화면.

6. 구역과 역할 — 폴더가 곧 담당

바이브 코딩에서 충돌은 AI가 남의 파일을 건드릴 때 생깁니다. 그래서 자기 구역 폴더만 수정하고, 구역 사이는 contracts/로만 연결합니다.

구역폴더하는 일
A-pipelinepipeline/, data/download_log.csv수집·정제·공간조인·gap·집계 (F1~F4)
B-validationvalidation/V1~V5, 부산 현장 실측
C-webweb/지도·사분면·슬라이더·목록 (F5~F7, F9~F12, F17)
D-docsdocs/게이트 보고서, 결정 기록, 발표 자료
E-serverserver/API, Docker Compose, Ubuntu 배포 (F15, F16, F18)
  • 각 구역 폴더의 CLAUDE.md에 그 구역 전용 규칙이 있습니다. AI 세션은 자동으로 읽습니다.
  • 공유 파일 config.yaml(분석 설정값), contracts/(API 응답 스키마·샘플)는 단독 PR로만 고치고 팀에 공지합니다.
  • 남의 구역에 수정이 필요하면 직접 고치지 말고 이슈로 요청합니다.

7. 개발 환경

처음 한 번

git clone git@github.com:HC1ab/onroad.git
cd onroad
sh scripts/setup.sh        # 훅 설치, .env 생성
gh auth login              # 이슈를 읽고 쓰려면 필요

Windows에서는 한글 파일명이 깨지지 않게 git config --global core.quotepath false도 권장합니다. 인증키가 필요하면 .env에만 넣습니다.

로컬 실행 (local 환경)

docker compose up          # DB(:5432) + API(:8000)
cd web && npm run dev      # 프론트(:5173), /api 는 :8000 으로 프록시
아직 준비 중: docker-compose.yml, server/ 코드, web/ 프로젝트는 지금 저장소에 없습니다. E-server와 C-web 담당이 만들면 이 명령이 동작합니다.
  • 서버가 없어도 프론트는 mock 모드(VITE_API_MODE=mock)로 contracts/samples/의 JSON을 읽어 개발할 수 있게 만들 예정입니다(P1).
  • 로컬과 서버는 같은 Docker 이미지를 쓰고, 차이는 .env.local/.env.prod 값으로만 둡니다.

8. 작업 흐름 — 이슈가 곧 프롬프트

AI 세션은 저장소 파일은 읽지만 채팅 내용은 모릅니다. 그래서 모든 작업과 결정은 이슈와 문서로 남깁니다.

  1. 이슈에서 시작: 작업·수정 요청·결정 모두 이슈로 만듭니다. 템플릿(task, change-request, decision)을 채우면 그대로 AI에게 줄 프롬프트가 됩니다.
  2. 세션 시작: git pull --rebase origin main → gh issue view 번호 --comments → 브랜치 구역/번호-주제 (예: pipeline/12-f1-clean)
  3. 작업: 자기 구역 파일만 수정. 병렬로 AI를 여러 개 돌릴 때는 git worktree로 폴더를 나눕니다.
  4. 세션 종료: 한 일·수치·막힌 점·후속 작업을 이슈 코멘트로 남기고, 후속 작업은 새 이슈로 만듭니다.
  5. PR: 본문에 Closes #번호. 작게, 1~2일 안에. main은 보호되어 있어 PR + squash merge로만 들어갑니다.
  6. 결정이 나면 docs/decisions/NNN-제목.md에 기록합니다. 다음 AI 세션이 이 폴더를 읽습니다.

커밋 메시지는 type(구역): 내용 형식입니다. 예: feat(pipeline): F1 제외 사유 표 추가

이슈 라벨: 구역(A-pipeline 등), 종류(task, change-request, blocker, question, decision), 게이트(gate-A~gate-C).

9. 지켜야 할 규칙

이 저장소는 퍼블릭입니다. 코드, 커밋, 이슈, PR 모두 공개된다고 생각하고 씁니다.

올리면 안 되는 것

  • data/raw/, data/interim/, 엑셀·GeoPackage·Parquet
  • .env와 인증키 (코드·이슈·채팅·스크린샷 모두 금지)
  • 현장 실측 사진, 50MB 넘는 파일
  • git add . 대신 파일을 지정해서 add

쓰면 안 되는 표현

  • "위험", "위반", "불법", "시간을 늘려야 한다"
  • 점멸 정의 확정 전의 "부족 N%" 같은 확정형 수치
  • "~ 때문에", "늘리면 사고가 준다" 같은 인과 표현

써야 하는 표현

  • "점검 우선순위 후보"
  • "기록값이 기준식보다 짧음"
  • "짧음(gap>0, 정의 미확정)"

바꾸면 안 되는 기술 결정

  • 저장 좌표계 EPSG:4326, 거리 계산은 EPSG:5179
  • 읍면동 코드 adm_cd는 항상 문자열
  • 원본 파일은 수정 금지 (엑셀로 열어 저장 금지)
  • 분석 설정값은 config.yaml에서만 읽기
커밋하면 .githooks/pre-commit이 금지 경로·대용량·키 패턴을 자동으로 막습니다. 막히면 우회(--no-verify)하지 말고 파일을 빼세요.
